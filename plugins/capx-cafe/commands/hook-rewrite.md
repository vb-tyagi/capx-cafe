The first line is the only line most people read before they decide to keep going. Sharpen it **without lying
to earn the scroll-stop**. capx never writes this for you — **you** draft the openers from the draft's real
content, and casserole still checks the winner at send. The draft to work on: "$ARGUMENTS"

Follow these steps:

1. **Find the hook and the substance.** Split the draft into its **first line** (the hook you're rewriting)
   and the **body** (what the post is actually about). List the concrete, true things the body already
   contains — the real number, the specific thing built, the actual before/after, the surprising detail. Your
   new openers can only use what's really in there. If the body has no specific hook-worthy fact, say so —
   the fix is a better *post*, not a louder first line.

2. **Diagnose the current opener.** Name why it's weak in one line: is it vague ("big update today"),
   throat-clearing ("So I've been thinking…"), hype with no substance, or **engagement-bait** ("you won't
   believe" / "RT if…" / a manufactured cliffhanger)? That diagnosis tells you what to trade *in*.

3. **Draft 2-3 alternative openers.** Each must be:
   - **Grounded** — pulled straight from the body's real facts. Do NOT invent a number, a result, or a stake
     to make the line hit harder. A hook that promises something the body doesn't deliver is a bait hook.
   - **Specific over loud** — lead with the concrete detail. "Cut cold-start from 4s to 400ms" stops more
     scrolls than "HUGE performance win" — and it's what actually gets *through* the guard and read.
   - **Load-bearing** — the opener should make a real claim or state a real detail, not just tease one. If a
     line only works by withholding, it's bait; rewrite it to *state* the interesting thing.
   - **Structurally varied** — give the user genuinely different angles (the number, the tension, the plain
     statement of what changed), not three rewordings of the same line.

4. **Show the options and keep the body intact.** Present the openers as a numbered list next to the original
   first line so the user can compare. Leave the rest of the post unchanged unless a new hook makes the old
   second line redundant — if so, flag that one-line trim. Let the user pick, edit, or blend before anything
   ships.

5. **Ship the winner only on request.** If the user picks one and asks to post, send the full post (new hook
   + body) with `post_now { text }`. Otherwise just hand back the rewritten draft — this skill's job is the
   opener, not the schedule.

**Hard rules:** you sharpen, **casserole decides** — a baity or hype-only hook comes back `blocked` or
`held`; when it does, show the reason and fix the *content* (make the line more specific, drop the tease),
never reword it just to slip past the guard. And never manufacture a stake or a number the body can't back
up — a hook is only as honest as the post beneath it.
